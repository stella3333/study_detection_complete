# AI 智慧讀書專注偵測系統

本專題使用 **AMB82-MINI（RTL8735B）** 搭配相機，在開發板端執行人臉偵測、讀書計時、離席判斷及紀錄。獨立的 `dashboard.html` 可由電腦或手機瀏覽器開啟，透過區域網路存取開發板的 HTTP API，查看目前狀態、番茄鐘及離席歷史。

韌體使用 AmebaPro2 提供的 **SCRFD**（人臉偵測）與 **MobileFaceNet**（人臉辨識）模型；本專題的專注判斷依據是**是否偵測到有效人臉**，不是辨認特定使用者身分，也不能直接判斷使用者是否真的專心。即使人臉顯示 `unknown`，仍可視為偵測到人臉。

## 一、系統功能與計時規則

1. **啟動確認：** 開機後，連續偵測到人臉約 **15 秒**，才開始累積讀書時間。
2. **短暫離席寬限：** 計時開始後，人臉消失不超過 **30 秒**時仍繼續累積讀書時間，以容忍短暫遮擋或離開。
3. **離席暫停：** 自最後一次有效人臉偵測起超過 **30 秒**仍未返回，系統暫停讀書計時，離席次數增加 1，並新增離席紀錄。
4. **返回恢復：** 暫停後重新偵測到人臉，即恢復讀書計時，並補上離席返回時間及持續秒數。
5. **短暫漏偵測處理：** 韌體設定 **2 秒的人臉訊號寬限**，降低偶發漏偵測造成的狀態閃爍；離席判定仍以最後一次板端有效偵測時間為基準。
6. **番茄鐘：** 預設專注 **5 分鐘**、休息 **1 分鐘**；網頁可設定專注 **1～180 分鐘**、休息 **1～60 分鐘**，設定於下一階段生效。
7. **專注／休息：** 番茄鐘的專注倒數只在有效讀書計時累加時前進；休息階段不累積讀書時間，也不計離席，休息倒數不受人臉狀態影響。休息結束後自動進入下一輪專注；若此時沒有偵測到人臉，重新計算 30 秒離席寬限。
8. **休息提醒：** 專注結束時，保持開啟且正常連線的網頁會顯示休息提醒；關閉網頁不影響板端計時，但無法收到網頁彈窗。
9. **離席歷史：** 顯示離席開始時間、返回時間、離席持續時間，以及當日累積離席時間；最多保留最近 **50 筆**。
10. **日期時間：** 開發板透過 NTP 取得 **UTC+8** 時間，供離席紀錄顯示與日期統計使用。

> **資料保存限制：** 離席歷史及當日累積統計保存在開發板 RAM，按 Reset 或斷電後會清空；當日統計以離席開始日期歸屬，跨午夜的單次離席不會拆分成兩天。NTP 校時失敗或時間異常跳動可能影響日期及離席持續時間的正確性，詳見「已知限制」。

## 二、硬體與軟體需求

- AMB82-MINI／RTL8735B 開發板及相機模組
- USB 傳輸線
- Arduino IDE，已安裝 **AmebaPro2** 開發板支援套件
- 可互通的 Wi-Fi 區域網路（開發板與瀏覽器裝置須能互相連線）
- 電腦或手機瀏覽器
- 選用：VLC，用來觀看 RTSP 即時影像

## 四、編譯及上傳韌體

1. 在 Arduino IDE 開啟 `focus_detection_demo.ino`。
2. 修改程式開頭的 Wi-Fi 設定：

   ```cpp
   char ssid[] = "YOUR_WIFI_SSID";
   char pass[] = "YOUR_WIFI_PASSWORD";
   ```

   **請勿將真實 Wi-Fi 密碼提交至公開 GitHub Repository。** 發布程式前應將憑證改回佔位文字；若曾公開真實密碼，請更換密碼。
3. 選擇 **AMB82-MINI** 開發板及正確的 COM 埠，編譯並上傳。
4. 開啟 Serial Monitor，鮑率設定為 **115200**；如需重新啟動，按開發板 Reset。
5. 等待 Wi-Fi 連線及串流啟動，確認序列埠輸出包含下列資訊（IP 依實際網路而異）：

   ```text
   WIFI_CONNECTED,IP=192.168.1.154
   RTSP_URL=rtsp://192.168.1.154:554
   BOARD_API_URL=http://192.168.1.154/
   READY,OPEN_DASHBOARD_HTML_ON_COMPUTER
   ```

若持續顯示 `WIFI_CONNECTING`，請確認 Wi-Fi 名稱、密碼及網路連線。若顯示 `ERROR,VIDEO_STREAM_START_FAILED` 或 `ERROR,FACE_DETECTION_STREAM_START_FAILED`，請檢查相機、開發板設定及韌體，必要時重新啟動或上傳。

## 五、開啟網頁及觀看影像

1. 確認開發板與電腦／手機在**可互通的同一區域網路**。
2. 用瀏覽器開啟 `dashboard.html`。
3. 在「開發板網址」欄輸入 Serial Monitor 顯示的 `BOARD_API_URL`，例如 `http://192.168.1.154/`，按下「連線」。
4. 網頁顯示累積讀書時間、目前狀態、離席次數、番茄鐘、當日累積離席時間及離席歷史。
5. 需要更改番茄鐘時，輸入專注及休息分鐘數，按「儲存設定」；設定於下一階段生效。
6. 若要觀看開發板相機影像，可在 VLC 的「開啟網路串流」輸入 Serial Monitor 顯示的 `RTSP_URL`。

### API 更新與連線處理

- `/api/status`：網頁**每 1 秒**嘗試更新讀書狀態、計時及番茄鐘。
- `/api/history`：網頁**每 5 秒**嘗試更新離席歷史及當日累積離席時間。
- 同類型請求尚未完成時，網頁不會再發送重疊請求。
- 單次 API 請求設有約 **4 秒逾時**；若暫時失敗，畫面保留上一次成功取得的資料，待後續請求成功再更新。
- **API 中斷後顯示的秒數可能跳號**：例如 35 秒後恢復直接顯示 40 秒，這代表網頁未收到中間更新，不一定是板端漏計。
- 關閉網頁不會停止開發板端的計時及離席紀錄。

## 六、計時驗證流程

| 階段 | 操作 | 預期顯示 |
|---|---|---|
| 啟動確認 | 正面坐在鏡頭前，連續保持約 15 秒 | `確認專注中`，之後轉為 `讀書計時中` |
| 正常讀書 | 持續出現在鏡頭前 | 累積讀書時間增加 |
| 短暫離席 | 人臉消失，但未超過 30 秒 | `暫時離開（計時保留）`，讀書時間仍增加 |
| 超時離席 | 人臉持續消失超過 30 秒 | `已暫停，等待返回`，離席次數增加、歷史新增紀錄 |
| 返回座位 | 重新出現在鏡頭前 | 恢復讀書計時，離席歷史補上返回時間與持續秒數 |
| 番茄鐘切換 | 將專注與休息設定為各 1 分鐘，完成專注階段 | 網頁提醒休息，休息倒數開始；結束後進入下一輪專注 |

> 建議使用手機拍攝開發板與操作過程，同時錄製網頁及 VLC 畫面，保留狀態轉換作為展示證據。番茄鐘倒數依有效專注時間前進，因此測試時須維持符合計時條件。

## 七、第三週測試與改善

依課程要求，至少完成三類情境，每類 **10 次獨立測試**，共 **30 次初測**；完成至少一項改善後，再針對受影響條件進行至少 **10 次重測**。每次須重新呈現目標或重新操作，不可把連續影片中的相鄰影格當成不同次測試。

| 測試類型 | 測試內容 | 測試目的 |
|---|---|---|
| 正常情境 | 正面、一般室內光線、正常讀書距離 | 確認可正常偵測並啟動計時 |
| 干擾情境 | 改變距離、臉部角度（0°／30°／45°）、光線或遮擋 | 評估不同條件對人臉偵測的影響 |
| 無目標／非目標情境 | 空椅子、遮住鏡頭、書本、衣物等 | 確認沒有有效人臉時不會錯誤啟動計時 |

### 改善項目：遠距離人臉偵測

初步測試發現，原版本在距離鏡頭超過約 **55 cm** 時容易無法偵測到人臉。經調整人臉偵測相關設定後，已**初步觀察**到約 **110 cm** 仍可偵測人臉，但 **120 cm** 未能成功偵測。

改善後規劃以 **50、60、80、100、110、120 cm** 等距離，搭配正面 **0°**、側臉 **30°**、側臉 **45°** 進行至少 10 次獨立重測，記錄是否偵測到人臉、是否啟動讀書計時，以及實際結果是否符合預期。實際修改的程式參數、測試成功次數及成功率，應在完成測試後補入報告；上述距離為初步觀察，並非已證實的穩定偵測上限。

建議紀錄格式：

| 條件 | 測試編號 | 預期行為 | 實際行為 | 是否符合預期 | 備註 |
|---|---|---|---|---|---|
| 改善後重測 | R01 | 連續偵測 15 秒後開始計時 | 待測 | 待填 | 正面、60 cm |
| 改善後重測 | R02 | 連續偵測 15 秒後開始計時 | 待測 | 待填 | 側臉 30°、80 cm |

**判定原則：** 「是否符合預期」須依測試前設定的預期行為填寫。若預期在 120 cm 能啟動計時、實際卻無法偵測，應記錄「不符合」，並在備註說明該距離可能超出桌前讀書的主要使用需求；不能為了提高成功率而事後修改判定。

## 八、常見問題與已知限制

- **VLC 有人臉框但顯示 `unknown`：** 本系統只需判斷是否有人臉，不要求註冊或辨識特定身分。
- **無法偵測人臉：** 確認臉部完整入鏡、光線充足、鏡頭高度適當；距離過遠、側臉或遮擋可能降低偵測效果。
- **網頁顯示 API 連線失敗：** 檢查開發板 IP、Wi-Fi 與裝置互通性；校園／訪客網路可能啟用用戶端隔離。暫時失敗時網頁保留上次資料。
- **計時沒有開始：** 必須連續偵測到有效人臉約 15 秒；若中途漏偵測，確認過程可能重新開始。
- **離席後沒有立即暫停：** 30 秒內是刻意設計的寬限時間；超過門檻才會暫停。
- **日期顯示空白：** 開發板尚未成功取得 NTP 時間，請檢查網路與 `CLOCK_SYNCED`／`WARNING,CLOCK_SYNC_FAILED` 訊息。
- **離席日期或持續時間異常：** 現有韌體部分持續時間計算會使用 NTP 時間戳記差值；若校時發生跳動，可能造成異常。`millis()` 備援不代表已完全排除此問題。
- **跨日統計限制：** 當日總計依離席開始日期歸屬，未將跨午夜的單次離席拆分到不同日期；統計只涵蓋本次開機期間。
- **資料不會永久保存：** 紀錄存於 RAM，重新啟動或斷電後清空。
- **不具備活體或專注程度辨識：** 照片中的人臉也可能被偵測；系統不能保證使用者真的正在學習。

## 九、後續改善方向

- 針對不同距離及側臉角度，重複測試並確認偵測穩定性。
- 檢查 NTP 校時與離席持續時間計算，降低日期異常對統計的影響。
- 進行較長時間的連續運作測試，觀察 API、讀書計時及離席紀錄是否穩定。
- 視需求增加紀錄持久化儲存，避免開發板重啟後資料遺失。
